# PixAI 웹 대기열

로그인된 PixAI 한국어 새 이미지 에디터에서 프롬프트를 순서대로 생성하고, 작업별 원본 이미지 전부와 JSON 기록을 저장하는 Tampermonkey 유저스크립트입니다. 브라우저 기능에 따라 저장 방식을 자동 선택합니다.

**검증 대기 후보:** 로컬 문법/모의 검증은 통과했으나 실제 폴더 선택, 사이트 조회, 원본 다운로드, 크레딧 차감은 아직 검증하지 않았습니다.

**브라우저:** Chrome/Edge 등 폴더 선택 API가 있으면 선택한 폴더에 직접 저장합니다. Firefox 등 해당 API가 없으면 Tampermonkey를 통한 브라우저 자동 다운로드를 사용합니다. 다운로드 완료 알림이 와야 저장 성공으로 처리하며, 준비 확인이 끝나기 전에는 생성 시작을 막습니다.

## 설치 · 업데이트

[유저스크립트 설치 / 최신판으로 업데이트](https://raw.githubusercontent.com/cotton100/pixai-web-queue/main/pixai-web-queue.user.js)

1. 데스크톱 Firefox/Chrome/Edge에서 최신 Tampermonkey를 설치합니다.
2. 위 링크를 열어 Tampermonkey 설치 화면에서 설치 또는 업데이트합니다. 기존 수동 설치판과 이름·namespace가 같으므로 기존 항목의 업데이트인지 확인합니다. 두 스크립트를 함께 켜두지 마세요.
3. PixAI 탭을 새로고침합니다. 현재 제목은 **0.1.7 후보**입니다. 0.1.6부터 다운로드 권한이 추가됐으므로 Tampermonkey에서 요청하면 허용합니다.
4. Tampermonkey의 스크립트 업데이트 확인을 켜두면 새 버전이 주기적으로 확인됩니다. 즉시 가져오려면 Tampermonkey에서 업데이트 확인을 실행합니다. GitHub에 수정본을 올린 뒤에도 열려 있던 PixAI 탭은 새로고침해야 새 코드가 적용됩니다.

업데이트는 코드의 `@version`, `@updateURL`, `@downloadURL`로 연결합니다. 코드 수정 후 GitHub에 올리고 버전을 높여야 새 버전으로 감지됩니다. 로컬 파일만 수정하면 배포되지 않습니다. 기존 대기열과 패널 위치의 사이트 저장 키는 유지합니다.

## 사용

1. [PixAI 새 이미지 에디터](https://pixai.art/ko/generator/image)에서 로그인하고 모델·LoRA·해상도·네거티브·이미지 수를 설정합니다.
2. 패널에 표시된 저장 방식을 준비합니다. Chrome/Edge는 **저장 폴더 선택**을 누르고 쓰기 권한을 허용합니다. Firefox는 아래 다운로드 설정 후 **자동 다운로드 준비 확인**을 누릅니다.
3. 작업 이름과 프롬프트를 입력합니다. 여러 프롬프트는 독립된 한 줄 `---`로 구분합니다. 반복 횟수는 생성 버튼을 누르는 횟수입니다.
4. 생성 1회 크레딧 상한을 입력하고 **대기열 추가**를 누릅니다. 기본 상한은 7,800, 빈칸은 제한 없음입니다. 비용을 읽지 못하거나 상한을 넘으면 제출하지 않습니다.
5. **시작 / 같은 작업 재개**를 누릅니다. 생성에는 계정 크레딧이 사용됩니다. 탭과 PC를 켜두세요.

제목줄을 마우스로 드래그해 패널을 옮길 수 있으며 위치를 기억합니다. 입력창과 버튼은 이동 영역이 아닙니다. **중지**는 다음 제출과 완료 확인을 멈추며 서버에서 이미 진행 중인 생성을 취소하지 않습니다.

## Firefox 자동 다운로드 설정

1. Firefox 설정의 **파일 및 애플리케이션 → 다운로드**에서 에셋을 저장할 폴더를 지정합니다. 자동 저장을 원하면 매번 저장 위치를 묻는 옵션을 끕니다. 이 폴더는 Firefox 전체 다운로드의 기본 위치입니다.
2. Tampermonkey 설정의 다운로드 모드를 **Browser API**로 설정하고 다운로드 권한을 허용합니다. 허용 다운로드 확장자에는 **png, jpg, webp, json**이 필요합니다. Blob 다운로드에는 최신 Tampermonkey가 필요합니다.
3. PixAI 탭을 새로고침하고 패널의 **자동 다운로드 준비 확인**을 누릅니다. 작은 `PixAI_다운로드확인_시간.json`이 저장됩니다. 파일은 비민감한 앱 이름·버전·확인 표시만 포함하며 이미지 생성이나 크레딧 사용은 없습니다.
4. 확인 파일이 원하는 위치에 저장됐는지 확인한 뒤 시작합니다. 확인 파일 다운로드 실패/취소/시간 초과 시 시작 버튼을 누르면 준비가 필요하다는 안내를 표시하고 생성을 막습니다. 이후 원본 또는 JSON 다운로드가 실패하면 다음 생성으로 넘어가지 않습니다.

브라우저 다운로드가 사용하는 절대 경로를 스크립트는 읽거나 보장할 수 없습니다. 실행 중 브라우저 다운로드 위치를 바꾸지 마세요. 브라우저가 이름 충돌을 처리하므로 실제 이름에 숫자가 붙을 수 있습니다. JSON의 파일명은 요청 이름이며 이 한계를 함께 기록합니다. 다운로드 완료 알림은 확인하지만 실제 파일 바이트를 다시 읽는 검증은 직접 폴더 저장 모드에서만 합니다.

## 버튼 무반응 진단

0.1.6의 **시작 버튼**은 설정 부족·다운로드 준비 전이면 비활성화돼 클릭 이유 안내도 없었습니다. 0.1.7은 실행 중이 아닐 때 시작을 클릭할 수 있게 하고, 실제 제출 전 검사에서 부족한 설정을 표시합니다. 준비 다운로드가 진행 중이면 완료를 기다리라는 안내, 준비 전/실패 후에는 준비 확인 안내, 폴더 미선택/권한 거부에는 저장 폴더 안내가 나옵니다. 저장 준비가 끝났어도 대기열이 비어 있으면 프롬프트 입력과 대기열 추가를 안내합니다. 실행 중 중복 시작 차단과 제출 전 저장 준비 검사는 유지합니다.

사용자 환경이 Firefox임을 확인했습니다. Firefox에서 폴더 선택 창이 열리지 않는 기능상 원인은 API 미지원입니다. 다만 대기열 추가까지 무반응인 원인은 별도로 미확정입니다. 0.1.5부터 각 버튼에 직접 pointer/click 입력 처리를 붙이고, 버튼을 누르면 바로 아래에 `입력 확인: 버튼 이름`을 표시합니다. 마우스 놓기 뒤 클릭 중복과 키보드 입력 처리도 유지합니다. 실제 Firefox 입력 개선 여부는 미검증입니다.

0.1.6은 폴더 API 미지원 환경에서 자동 다운로드를 선택하고 설정이 부족하면 처음부터 준비 안내를 표시합니다. 페이지 내부 JavaScript 접근이 필요하지 않아 실행 환경은 `DOM`으로 지정했고, 다운로드 및 모드 확인용 `GM_download`/`GM_info` 권한을 선언했습니다.

### 이전 0.1.4 진단 표시

0.1.3에서 폴더 버튼이 무반응이라는 보고가 있어 버튼 입력과 상태 표시를 보완했습니다. 사이트의 다른 이벤트 처리에 앞서 이 폴더 버튼만 처리하며, 마우스와 키보드로 직접 누르는 입력을 지원합니다. 마우스 놓기와 뒤따르는 클릭은 한 번의 선택창 호출로 합칩니다. 일반 사이트 조작이나 제목줄 드래그에는 이 처리를 적용하지 않습니다.

상태와 오류 문구는 **폴더 버튼 바로 아래**에 표시합니다.

- `입력 전달됨 · 폴더 선택창 여는 중…`: 버튼 입력이 처리되고 선택창 호출을 시작했습니다.
- `폴더 선택창 응답 대기 중`: 8초 동안 브라우저 선택창 응답이 오지 않았습니다. Alt+Tab으로 다른 창 뒤에 열린 선택창이 있는지 확인하세요. 선택창을 자동 재호출하지 않습니다.
- `폴더 선택됨 · 쓰기 권한과 기록 확인 중…`: 선택창에서 폴더를 선택했고 후속 확인 중입니다.
- `저장 폴더 선택 완료: 폴더명`: 선택과 확인이 끝났습니다.
- API/권한/취소 오류가 발생하면 같은 위치에 오류를 표시합니다.

0.1.4는 document-start 등록과 페이지 실행 환경(raw)을 사용했지만 사용자의 무반응을 해결하지 못했습니다. 0.1.6에서도 실제 버튼 반응은 사용자 화면에서 확인해야 합니다.

## 저장 · 복구

- 한 번 제출 → 같은 작업 ID 완료 확인 → 원본 전부 저장 → JSON 기록 → 다음 작업 순서입니다. 사이트에서 4장 묶음을 선택하면 4장 모두 저장합니다.
- 대기열은 같은 브라우저 프로필의 PixAI 사이트 저장소에 남습니다. 새로고침 후 자동 실행하지 않으며 폴더를 다시 선택하거나 다운로드 준비 확인 후 시작해야 합니다.
- 제출 결과가 불명확하면 자동 재제출하지 않습니다. 사이트에서 해당 작업을 확인하고 ID를 연결하거나 건너뛰세요.
- 직접 폴더 저장은 실패 후 같은 작업의 남은 이미지만 저장하며, 동일 폴더를 확인해야 재개합니다. 자동 다운로드는 저장 위치의 동일성을 확인할 수 없어 수동 재개 때 같은 작업의 원본 전부를 추가 사본으로 다시 다운로드합니다. 이전 파일/진행 기록은 보존하며 두 방식 모두 이미지를 재생성하지 않습니다.
- 폴더 핸들 기록이 실패해도 현재 탭에서는 사용할 수 있으며 경고를 표시합니다. **이 경고가 있으면 부분 저장 중 새로고침하지 마세요.** 기록이 없으면 새로고침 후 동일 폴더 검증을 할 수 없어 자동 재개를 막습니다.
- 기존 파일을 덮어쓰거나 삭제하지 않습니다. 중단된 파일은 재시도 때 숫자가 붙은 추가 사본이 생길 수 있습니다.
- 오류 문구는 폴더 버튼 바로 아래에 표시됩니다. 폴더 선택 오류가 계속되면 오류 종류와 문구를 확인하세요.

## 범위 · 제한

작업별 전체 설정 스냅샷은 없습니다. 모든 작업은 시작 시 사이트의 공통 설정을 사용합니다. 실행 중 사이트 조작은 중지 처리합니다. 다른 탭에서 수동 생성이나 설정 변경을 함께 하지 마세요. 같은 프로필 내 대기열 중복 실행은 브라우저 잠금으로 막습니다.

생성은 사이트 버튼을 이용하고 완료 확인과 원본 URL 조회는 사이트 내부 GraphQL을 사용합니다. 사이트 변경이나 인증 방식에 따라 깨질 수 있습니다. 쿠키·토큰·인증 헤더를 직접 읽거나 복사하지 않습니다. 다운로드는 HTTPS PixAI 호스트만 허용하며 썸네일이나 ZIP으로 임의 대체하지 않습니다.

실제 Chrome 브라우저의 입력창/생성 버튼/작업 카드 구조를 읽기 확인했지만 실제 폴더 선택·Firefox 버튼 입력/자동 다운로드·프롬프트 반영·신규 작업 수신·내부 조회·원본 다운로드 CORS·저장·실제 차감·연속 생성은 **미검증**입니다. Firefox는 현재 연결된 브라우저 도구에 노출되지 않아 실화면에서 검사하지 못했습니다.

## 개발 · 검증

Node.js의 기본 기능만 사용하며 별도 패키지 설치는 필요 없습니다.

```sh
node --check pixai-web-queue.user.js
node --test verify.cjs
```

npm을 사용하는 환경에서는 `npm test`로 두 검사를 함께 실행할 수 있습니다.

문법 검사와 모의 테스트를 실행합니다. 모의 테스트는 제출 불명 시 재생성 금지, 저장 재개, 비용 상한, 순차 처리, 드래그와 위치 복원, 폴더 권한과 기록 실패를 검사합니다. 모의 검증은 사이트 호환성 증명이 아닙니다.

0.1.4: 모의32건 통과. 기존25건에 폴더 입력 전달/중복 방지/키보드 입력/취소·비활성·다른 영역 입력 제외, 선택창 즉시 호출, 미응답 대기 표시, API 없음·호출 실패·취소 처리를 추가했습니다.

0.1.5: 모의36건 통과. 지원 여부 검사와 전체 스크립트의 모의 DOM 장착 검증을 추가했습니다. Firefox와 같은 API 미지원 환경에서 최초 안내/시작 차단, 클릭 이벤트 없이 버튼에서 직접 마우스 놓기 입력으로 빈 프롬프트 검증 실행, 지원 환경의 선택창 1회 호출/취소 표시를 확인했습니다. 모의 DOM은 실제 Firefox/PixAI 화면 검증이 아닙니다.

0.1.6: 모의43건 통과. 브라우저 기능별 저장 모드 선택, 다운로드 모드/권한 안내, Blob 전달/완료 대기/이름 충돌 보존/오류·시간 초과·늦은 콜백, Firefox 준비 확인 완료 전 시작 차단, 부분 저장 재개 시 과금 없는 전체 재다운로드, 저장 실패 후 다음 생성 차단을 검증했습니다.

0.1.7: 모의46건 통과. 설정 부족/준비 전/준비 진행 중/실패 후/폴더 미선택/권한 거부/빈 대기열에서 시작 버튼이 이유를 표시하고 사이트 조회·원본 생성 버튼 호출을 하지 않는지 검증했습니다. 실행 중에만 시작이 비활성화되고 준비 실패 후 다시 클릭 가능한지도 확인했습니다. 실제 Firefox 클릭·다운로드·유료 생성 성공은 미검증입니다.
