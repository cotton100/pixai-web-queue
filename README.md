# PixAI 대기열

프리셋·캐릭터·청크·씬을 조합해 여러 이미지를 예약하고 원본을 저장하는 **비공식 유저스크립트**입니다. 공식 API 실행과 사이트의 웹 무제한 실행을 구분해 사용합니다. PixAI와 제휴하지 않았으며 각 기능에는 PixAI의 이용 조건이 적용됩니다.

**0.10.21**은 같은 PC 앱과 동기화할 때 일괄 구성의 **추가 청크·문구 순서를 보존**하고, 스크립트의 씬 화면에서도 이를 선택·편집할 수 있습니다. 동기화에는 **Pixais 앱 0.1.24 이상**이 필요하며 0.1.23 이하에서는 연결할 수 없습니다. 아래 설치 링크는 각 공개 브랜치에 게시된 버전을 제공합니다.

[사용 설명서](GUIDE.md) · [안정판 설치·업데이트](https://raw.githubusercontent.com/cotton100/pixai-web-queue/main/pixai-web-queue.user.js) · [개발판 설치·업데이트](https://raw.githubusercontent.com/cotton100/pixai-web-queue/develop/pixai-web-queue.dev.user.js) · [배포 안내](RELEASE.md)

- **조합 예약:** 프리셋·캐릭터·청크를 고르고 순서와 이미지 설정을 예약마다 보관합니다. 접은 그룹에도 현재 선택이 표시됩니다.
- **씬·일괄 예약:** 캐릭터·출연과 씬을 각각 여러 개 골라 조합합니다. 왼쪽의 **캐릭터·출연 / 씬 / 관리**로 목록을 전환하고, 캐릭터·출연 목록 아래에서 모든 조합에 붙일 **추가 청크**를 고릅니다. 추가 청크 순서와 **캐릭터·출연 / 씬 / 추가 청크**의 문구 순서도 끌어서 바꿀 수 있습니다. 작은 화면 모드와 마지막 탭도 기억합니다.
- **편집과 정리:** 폴더·항목 드래그, 여러 항목 이동·복제·삭제, 씬 안 청크 사본 편집을 지원합니다. 선택 안내는 상단에 표시하며 새 항목 버튼을 덮지 않습니다.
- **실행과 저장:** 하단 실행 줄에서 방식과 시작·중지를 고릅니다. **실행 방식 도움말(?)**은 키보드나 클릭으로 열 수 있습니다. 완료 항목은 기록으로 이동하며 별도 JSON 파일을 자동 생성하지 않습니다.
- **같은 PC 라이브러리 연결:** 앱과 재료만 함께 사용합니다. 처음 합치기와 충돌은 미리보기를 확인한 후 반영합니다. API 키·예약·대기열·이미지는 동기화하지 않습니다.

처음에는 **재료 저장 → 조합 예약 → 대기열 등록 → 첫 작업만 실행 → 저장·기록 확인** 순서로 사용하세요. 예약과 등록만으로는 생성 요청을 보내지 않습니다. 공식 API 생성에는 크레딧이 사용됩니다.

## 업데이트 전

기존 스크립트를 삭제하지 말고 업데이트하세요. **전체 설정 내보내기**와 **대기열 백업**을 각각 보관하고, 아직 저장하지 않은 입력을 먼저 저장하거나 복사합니다. 업데이트 후 이미 열려 있는 PixAI 탭도 새로고침하세요.

저장 용량 오류를 줄이기 위해 큰 라이브러리·대기열 본문은 Tampermonkey 전용 저장소에 보관합니다. 저장 확인 후 연결 정보를 전환하며, 전환된 자료는 구버전에서 읽지 못할 수 있습니다. 사이트 데이터만으로 이 본문을 복원할 수는 없습니다. 스크립트·확장 프로그램·사이트 데이터를 지우기 전에는 백업을 받으세요.

앱 0.1.22의 선택 백업 파일과 기존 스크립트 백업 호환은 유지합니다. 파일 백업을 가져오는 기능과 앱 0.1.24 이상을 요구하는 실시간 동기화는 별개입니다.

## 처음 사용

[기존 설치/업데이트 주소](https://raw.githubusercontent.com/cotton100/pixai-web-queue/main/pixai-web-queue.user.js). GitHub 반영 여부를 확인하고 업데이트합니다. 스크립트 이름·namespace는 유지했으므로 기존 항목을 업데이트하고 같은 스크립트 두 개를 동시에 켜지 않습니다. 최신 Tampermonkey의 PixAI API/이미지 도메인 접근 권한이 필요합니다.

1. 설치한 버전과 패널 제목을 확인합니다. **조합 예약 → 이미지 설정**을 펼쳐 비율·크기·생성 모드·생성당 이미지 수를 고릅니다. 프리셋·캐릭터 선택 바로 아래에 있으며, 처음에는 접혀 있습니다.
2. 공식 API 방식이라면 설정 → 공식 API 키 → **이 탭에 키 연결**. 입력란을 즉시 비우며 기본값은 탭 메모리 보관입니다. 기본 모드에서는 새로고침하면 다시 입력합니다. 필요하면 **이 브라우저에 API 키 기억하기 (선택)**를 체크한 뒤 연결합니다. 이 도구의 설정·대기열 백업에는 키를 넣지 않습니다.
3. **기존 작업으로 연결 확인**은 조회만 합니다. ID 입력이 비어 있으면 대기열의 첫 기존 ID를 사용합니다. 키 입력과 인증 성공은 구분합니다.
4. 저장 위치를 준비합니다. Chrome/Edge는 폴더 선택·쓰기 권한, Firefox는 Tampermonkey Browser API 다운로드 설정·준비 확인이 필요합니다. Firefox 저장 위치는 브라우저 다운로드 설정을 따릅니다.
5. 모델/LoRA는 조합 프리셋으로 지정합니다. 통짜 작업은 기본 모델 **버전** ID를 입력할 수 있고, 비어 있으면 첫 실행에서 사이트 모델/LoRA·네거티브를 읽습니다. 모델 페이지 ID와 버전 ID는 다릅니다.
6. **조합 예약 → 이미지 설정**에서 비율·크기, **모델 기본값 / Lite / Standard / Pro / Ultra**, **1장 / 4장 배치**를 고릅니다. 접으면 선택한 네 값이 제목줄에 남습니다. 스타일·시드와 미리 등록할 작업 수(1~10개)는 **설정**에서 정합니다. 사이트 해상도·스타일·참조 설정은 복사하지 않습니다. 모드는 **모델 기본값 (모드 보내지 않음)**을 권장합니다. Tsubaki.3에 `standard`를 보내면 서버가 inferenceProfile을 인식하지 못해422로 거절한 실측이 있습니다. 다른 모드의 실호환성은 미검증입니다. 새 예약과 대기열 등록 시 API 옵션·배치 수를 각각 보관합니다.
7. 공식 API 생성은 크레딧을 사용합니다. **기존 사이트 비용 상한은 API에 적용할 수 없습니다.** 설정의 안내를 확인하고 생성당 1장인 작업을 등록한 뒤 **첫 작업만 실행**으로 시험합니다. 이 버튼은 작업 1건을 처리하므로 4장 배치 작업이면 4장을 생성합니다. 첫 미완료 작업이 대기이면 새 생성이고, ID가 있으면 조회·저장만 재개합니다.

## 같은 PC 앱과 라이브러리 동기화

**0.10.22**는 앱 0.1.25와 같은 자유 문구 순서를 지원합니다. 조합에서 청크를 공통문·캐릭터 앞으로도 옮길 수 있고, 미리보기·예약·최근/즐겨찾기·실제 전송 및 백업에 그 순서가 유지됩니다. 전체·선택·앱 호환 백업으로 양방향 이동할 수 있습니다. 씬은 청크 묶음이므로 공통문·캐릭터 사이의 전체 배치는 조합 즐겨찾기로 저장하세요.

앱 0.1.25의 프리셋·공통문 폴더 정보도 보존합니다. 폴더 편집은 앱에서 하고, 스크립트는 기존 목록·편집기를 사용하면서 소속과 순서를 유지합니다. 새 폴더나 자유 순서 자료는 구형 스크립트에서 열 수 없으므로 양쪽 업데이트 후 사용하세요. 상세·검증 범위는 [배포 안내](RELEASE.md)에 정리했습니다.

**스크립트 0.10.21 + Pixais 앱 0.1.24 이상**을 사용하세요. 처음에는 연결하지 않은 상태이며, 앱의 같은 PC 연결을 켠 뒤 일회용 코드를 스크립트의 **설정 → 같은 PC 앱과 라이브러리 연결**에 입력합니다. 자세한 순서는 [사용 설명서](GUIDE.md#같은-pc-앱과-라이브러리-동기화)를 참고하세요.

공통문·프리셋·캐릭터·청크·씬·출연·저장한 일괄 구성과 관련 폴더·순서·연결을 공유합니다. **API 키, 예약과 실행 대기열, 최근·즐겨찾기, 생성·화면 설정, 이미지·저장 경로는 공유하지 않습니다.** 이미 만든 예약의 문구는 보존하며, 저장하지 않은 편집이나 생성이 진행 중이면 반영을 기다립니다.

저장한 일괄 구성의 추가 청크 선택·순서와 문구 합성 순서도 양방향으로 유지합니다. 기본 문구 순서는 **캐릭터·출연 → 씬 → 추가 청크**이며, 구성 화면에서 변경합니다. 추가 청크나 문구 순서 정보가 없는 예전 구성·예약은 기존 동작을 유지합니다. 새로 만든 예약에는 당시 추가 청크 문구와 순서를 사본으로 보관하므로, 이후 재료를 고치거나 동기화해도 기존 예약 문구는 바뀌지 않습니다.

**지금 동기화 → 첫 동기화 미리보기 → 미리보기 적용** 순서로 처음 합칩니다. 같은 항목을 양쪽에서 다르게 수정했다면 **양쪽 값 보기**를 확인하고 항목마다 **앱 값 사용 / 스크립트 값 사용**을 직접 고릅니다. 충돌 선택은 미선택으로 시작하며 모두 고른 뒤 적용합니다. 처음 한쪽에만 있는 항목은 삭제로 취급하지 않습니다. 연결 이후의 삭제도 동기화 대상이므로 필요하면 먼저 백업하세요.

**자동 동기화**를 켜면 충돌 없는 후속 변경을 자동으로 맞춥니다. 꺼 두어도 연결된 동안 10초 간격으로 앱의 요청을 확인하므로, 앱에서 수동으로 시작한 동기화는 받을 수 있습니다. 통신 자체를 멈추려면 **스크립트 연결 해제**를 누르세요. 해제는 라이브러리나 기존 예약을 삭제하지 않습니다. 동기화는 백업을 대신하지 않습니다.

## 웹 무제한 실행

하단 **대기열 실행 방식 → 웹 무제한 · 1장씩**을 고른 뒤 새 작업을 등록합니다. API 키 없이 사이트의 Tsubaki.3 무제한 모드를 사용하며, **한 장 생성 → 원본 저장 → 다음 작업** 순서로 처리합니다. 사이트에서 무제한을 사용할 수 있어야 하며, 전용 토글·무료 표시·단일 생성 여부를 확인하지 못하면 멈춥니다.

모델·LoRA·포지/네거·비율을 적용합니다. 프로 모드·해상도는 사이트 고정값이며 API 스타일·시드·PNG 요청 기록은 사용하지 않습니다. 자동 프롬프트 도우미는 끕니다. 기존 API 작업은 자동 전환하지 않고 두 방식의 미완료 작업이 섞여 있으면 실행을 중지합니다.

실행 중에는 같은 계정의 다른 탭에서 생성하거나 사이트를 직접 조작하지 마세요. 새 ID는 즉시 보관하고, 원본이 나온 뒤 작업 상세의 ID·0크레딧·프롬프트를 대조해 저장합니다. ID를 확보한 뒤 저장이 실패하면 같은 ID로 재개합니다. 상대 시간 문구로 성공을 판단하거나 자동 재생성하지 않습니다. 여러 작업 카드 때문에 재개가 막혔다면 해당 작업만 표시한 화면에서 다시 시도하세요. 사이트 구조가 바뀌면 웹 실행은 멈출 수 있습니다.

Chrome/Tampermonkey 0.10.19에서 **시작 한 번으로 서로 다른 2건 생성·원본 자동 저장·완료 기록 이동·새로고침 유지**를 확인했습니다. 두 결과는 각각 1280×768 WebP였습니다. 0.10.20은 같은 웹 실행 모듈을 사용하지만 Firefox 실사용까지 확인한 것은 아닙니다.

## 업데이트 채널

**설정 → 업데이트 채널**에서 안정판 또는 개발판을 고른 뒤 **선택한 채널 설치 화면 열기**를 누릅니다. Tampermonkey에서 기존 스크립트의 업데이트·재설치를 확인하고 PixAI를 새로고침하세요. 선택하거나 설치 화면을 열기만 해서는 전환되지 않습니다. 설치를 취소하면 현재 채널을 유지합니다. 현재 실행 중인 빌드와 관리자에서 보고한 자동 업데이트 주소를 별도로 표시합니다. 주소를 확인할 수 없거나 자동 업데이트가 꺼져 있으면 Tampermonkey에서 확인하세요.

두 설치 파일은 이름·namespace·권한·저장 키를 공유하며 데이터 이전·삭제를 실행하지 않습니다. 기존 항목을 삭제하지 말고 업데이트하세요. 전환 전 설정 백업을 권장합니다. 더 최신 개발판에서 이전 안정판으로 돌아가면 관리자에서 구버전 설치 확인이 나올 수 있습니다. 개발판은 실험 변경이 먼저 들어가므로 안정성과 향후 모든 버전 간 데이터 호환성을 보장하지 않습니다. Tampermonkey의 실제 교체·저장 데이터 보존은 모의 검사와 구분해서 검증합니다.

## 키 기억하기와 삭제

기억하기는 Tampermonkey의 **이 스크립트 저장소**에 키를 저장합니다. PixAI 사이트 localStorage에는 저장하지 않습니다. 다음 방문에는 저장된 키를 메모리로 불러오며 입력칸은 비워 둡니다. 자동으로 생성하거나 연결 확인 요청을 보내지 않습니다. 지원하지 않는 스크립트 관리자는 저장 없이 연결만 가능합니다.

체크만 하면 저장하지 않으며 **이 탭에 키 연결**을 눌러야 저장됩니다. 체크를 끄면 저장된 사본을 지우고 현재 탭의 메모리 연결은 유지합니다. **키 지우기**는 저장된 사본과 현재 탭의 연결을 지웁니다. 이미 열린 다른 탭의 연결은 각 탭에서 지워야 합니다.

암호화 금고가 아닙니다. 확장 관리자 백업·동기화에는 키가 포함될 수 있고, 기기·확장 관리자에 접근할 수 있는 사람으로부터 키를 보호한다고 보장하지 않습니다. 공용 PC에서는 저장하지 않는 것을 권장합니다. 저장하지 않는 방식도 사용 중인 페이지 입력란·메모리까지 안전을 보장하는 것은 아닙니다. 업데이트 시 스크립트 저장소 권한 추가 안내가 나올 수 있습니다.

## 대기열 정리

- **진행 대기열**에는 아직 완료하지 않은 작업을 표시합니다. 저장이 끝나면 **완료·보관 기록**으로 자동 이동합니다.
- 작업 제목 왼쪽에서 선택한 뒤 **선택 삭제**, 또는 **현재 목록 전체 삭제**를 사용합니다. 현재 탭에 표시한 목록만 대상이며 건수 확인 후 적용됩니다. 삭제한 기록은 복구할 수 없으므로 필요하면 대기열 백업을 먼저 받습니다. 이미지 파일·프리셋·청크는 삭제하지 않습니다.
- **새 대기열**은 미제출 작업을 기록으로 보관하고 진행 목록을 비웁니다. 기록의 **건너뛰기 취소**로 다시 가져올 수 있습니다. 새 작업 등록은 기존 조합 화면에서 합니다.
- 실행 중에는 정리할 수 없습니다. 이미 제출했거나 제출 결과가 불명확한 미완료 작업은 삭제·새 대기열 대상에서 보호합니다. 전체 삭제가 막히면 안전한 항목만 선택 삭제하거나, 보호된 작업을 같은 ID로 재개해 저장을 마칩니다.

## 보존·복구와 제한

받은 작업 ID는 유지합니다. 재개할 때 기존 ID부터 처리하고, 제출 응답 유실·시간 초과·판단 불가 5xx는 자동 재전송하지 않습니다. 저장 실패는 같은 ID의 다운로드·저장만 재개합니다. 기존 파일을 덮어쓰지 않습니다. 중지는 새 제출을 멈추며 서버 작업을 취소하지 않습니다. 활성 작업 조회 간격은 5초이며 웹훅은 사용하지 않습니다.

API 옵션은 설정 백업에, 확정 요청과 저장 이력은 브라우저 대기열과 수동 대기열 백업에 포함합니다. 세션 키와 별도로 기억한 API 키는 이 도구의 백업에서 제외합니다. 0.9.5부터 이미지 옆 JSON 자동 저장은 제거했습니다. 기존 JSON 파일을 삭제하지 않으며 설정/대기열 백업 버튼은 유지합니다. 공식 응답에 프롬프트가 없으면 ID·생성 시각만 검증하며, 로컬 요청 사본을 서버 확인 정보로 표시하지 않습니다.

설정 변경은 이미 확정된 대기 요청에 자동 반영되지 않습니다. 미제출 대기 작업의 **현재 API 옵션 적용**을 누르면 해당 작업만 다시 확정합니다. 이전 요청은 `apiRequestHistory`에 보존하며 프롬프트·모델/LoRA·조합·기존 랜덤 시드는 유지합니다. 작업 ID가 있거나 제출 결과가 불명확하거나 저장된 출력이 있으면 요청을 바꾸지 않습니다. 버튼은 새 생성을 실행하지 않습니다.

비율은 **가로:세로**입니다. **5:3은 가로**, **3:5는 세로**입니다. 대기열 카드에 실제 적용할 비율·크기가 표시되며 현재 선택과 다르면 안내합니다. 비율·크기 선택 아래의 **기존 대기 작업의 비율·크기 변경**을 펼친 뒤 **미제출 대기 작업에 비율·크기 적용**을 누르면 변경 가능한 대기 작업만 한 번에 갱신합니다. 기존 모델/LoRA·프롬프트·모드·시드·배치 수와 이전 요청 사본을 보존합니다. 이미 제출한 작업·완료 작업·제출 결과가 불명확한 작업은 대상에서 제외합니다.

조합 예약의 **프리셋·캐릭터 선택 바로 아래**에 **비율·크기·생성 모드·생성당 이미지 수** 버튼 목록이 있습니다. 좁은 화면에서는 **재료** 탭에서 고릅니다. 새 예약은 화면에서 고른 네 값을 각각 보관합니다. 예를 들어 가로 5:3·Pro·4장 예약과 세로 3:5·Ultra·1장 예약을 함께 등록할 수 있습니다. 선택값은 최근 조합·즐겨찾기·설정 백업에도 보존되며, 같은 재료라도 이미지 설정이 다르면 별도 조합으로 기록합니다. 이전 예약에 없는 옵션은 대기열 등록 시점의 선택값을 적용합니다. 이미 등록한 작업은 선택 변경만으로 바뀌지 않습니다. **현재 API 옵션 적용**은 모드·배치 수도 갱신하고, **미제출 대기 작업에 비율·크기 적용**은 모드·배치 수를 유지하므로 적용 대상을 확인하세요.

청크와 캐릭터는 각각 폴더로 묶습니다. **이름 있는 폴더는 처음에 접혀 있고**, 미분류 목록은 펼쳐 있습니다. 같은 화면에서 직접 펼친 상태는 항목 저장·검색 후에도 유지합니다. 폴더 제목을 눌러 펼치고 항목을 누르면 그 자리에서 편집합니다. 폴더·항목의 ⠿ 손잡이로 순서와 소속 폴더를 바꾸고, 체크한 여러 항목을 이동·복제·삭제할 수 있습니다. 이동 대상에서 새 폴더도 바로 만들 수 있습니다. 폴더만 삭제하면 안의 항목은 미분류로 이동하고 프롬프트와 기존 예약은 유지됩니다. 캐릭터 폴더도 설정 백업에 포함됩니다. 백업은 최신 스크립트에서 불러오세요.

조합창의 프리셋·캐릭터·청크 선택과 순서·LoRA 트리거 위치·횟수·이미지 설정을 이 브라우저에 기억합니다. 과금 안내 체크도 체크/해제한 상태를 로컬에 보관합니다. 새로고침 시 편집 상태만 복원하며 자동으로 예약·등록·생성하지 않습니다. 과금 안내 체크와 현재 편집 상태는 설정 백업에 넣지 않습니다. 저장 실패는 화면에 알리며, 비율·크기 저장 실패는 선택값을 되돌립니다. 빈 횟수 입력은 마지막 유효 편집 상태를 덮어쓰지 않습니다. 설정 파일을 명시적으로 가져오면 편집 상태는 가져온 라이브러리에 맞춰 초기화합니다.

캐릭터 전용 LoRA가 있는 브라우저 라이브러리는 구버전에서 읽지 못하도록 보호합니다. 구버전으로 바꾸기 전에 최신 버전에서 전체 백업을 보관하세요. 캐릭터 LoRA를 포함한 상태의 **0.9.14 호환 내보내기**는 누락을 막기 위해 중단하며, 최신 전체·선택 백업을 안내합니다.

현재 전체·선택·앱 호환 백업은 일괄 구성의 추가 청크·순서와 예약 사본을 보존합니다. **0.9.14 호환 내보내기**에서는 추가 청크가 있거나 기본과 다른 문구 순서를 가진 예약을 보존할 수 없어, 제외 건수를 안내하고 해당 예약을 제외합니다. 이 기능을 쓰는 자료는 최신 형식으로 백업하세요.

LoRA 개수는 로컬에서 제한하지 않고 선택한 목록을 그대로 전송합니다. 서버가 한도 초과 등으로 거절하면 오류를 표시하고 이후 작업 제출을 멈추며 자동 재시도하거나 LoRA를 빼지 않습니다. 공식 API 제출에는 **수치 0~1·LoRA 버전 ID**가 필요합니다. 기존 음수/1 초과 수치를 임의로 바꾸지 않고 제출 전에 멈춥니다. 프리셋에서 고친 뒤 새 예약을 만듭니다. 조합에 넣은 트리거는 사용자 순서를 유지하고 API 자동 추가를 빈 사용자 트리거로 덮어쓰도록 구현했습니다. 실제 T3에서 중복 억제·위치 보존은 미검증입니다. 통짜 작업에 트리거 정보가 없으면 API 기본 트리거를 사용합니다.

0.9.4 당시 Tsubaki.3(버전2024383379556065549)·LoRA 3개(0.8/0.5/0.5)·4장 배치 2건 생성과 원본8장·JSON2개 자동 저장을 Chrome에서 확인했습니다. 테스트 전후 잔액은14,000크레딧 감소했습니다. 이 값은 해당 설정의 관측값이며 다른 모델·모드·크기에 대한 가격 보장이 아닙니다. Firefox 동작은 미검증입니다. Reference Pro·Edit·Edit Lite·영상은 API 미지원입니다. 자동 비용 상한·잔액·환불을 약속하지 않습니다.

- **일괄 예약**: 행/열 순서, 공통 반복, 쌍별 예외(0=제외), 씬별 이미지 옵션, 저장한 구성과 묶음 필터를 제공합니다. `3×3×2×4장 = 18작업·72장`. 바로 등록도 생성 버튼을 누르지는 않습니다. 실행 중인 대기열에 등록하면 기존 실행 정책에 따라 이어서 처리됩니다.
- **이미지 정보**: PNG 텍스트·alpha stealth·지원 EXIF/XMP·NAIS 로컬 기록을 브라우저에서 읽습니다. 출처를 고르고 필요한 항목만 선택해 새 조합·청크·프리셋으로 저장합니다. 모든 생성기 설정을 복원하는 기능은 아닙니다.
- **PNG 요청 기록**: 원본 PNG의 기존 청크와 픽셀을 보존해 iTXt를 추가합니다. 기록 삽입 실패는 원본 저장과 지속 경고로 처리하고, 실제 저장 오류는 실패로 남깁니다. 요청 시드는 결과별 확정 시드가 아닙니다.
- **백업**: 새 전체 백업 v2, 앱 0.1.11 호환 v1, 구형 스크립트 0.9.14 호환 v1을 구분합니다. 구형 형식의 제외 내역을 저장 전에 표시하고 예약 문구는 합쳐 보존합니다. 앱의 **앱용 백업**을 가져오세요. 앱의 기존 **스크립트용 내보내기**에서 이미 빠진 씬 등의 데이터는 복원할 수 없습니다.
